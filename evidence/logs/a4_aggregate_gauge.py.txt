        permute coefficients    39.177788    0.043402   1466.77

  The point of this table is the 'own MSE' column.  Every transform
  that damages the linear aggregate also damages the client's own
  model, so a functional audit catches it.  There is no move that is
  free for the client and costly for the average -- that gap is what
  the symmetry group opens up, and it exists only for the network.

A4.5  do canonicalisation defences close it?
============================================================================
  clean aggregate MSE                 0.501584
  layerwise-canon aggregate MSE       0.845742
  gauge-canon aggregate MSE           0.502319
  variance of teacher output          0.752754

  Layerwise normalisation divides W3 as well, so it rescales the
  OUTPUT: it is not a gauge move and it destroys the model on its
  own, before any attack.  Absolute MSE is reported for that reason;
  a ratio against a broken baseline would look like a defence.

              gauge move        raw   layerwise   gauge-canon
             global c1=8     0.5561      0.8452        0.5023
         per-unit sd=0.5     0.5062      0.8466        0.5023
         per-unit sd=1.5     2.1808      0.8474        0.5023
             permutation     0.4991      0.8471        0.4993

  Gauge canonicalisation fixes the per-unit scale by a move that
  stays inside the orbit, so it costs nothing and it does neutralise
  the continuous part of the group.  It does not touch permutation,
  for which no cheap canonical form exists: aligning hidden units
  across clients is an assignment problem.
